## F2 — Design ✅

| # | Feature | Type | Why it fits AfterBill |
|---|---|---|---|
| 1 | **Budgets** | New module (`budgets.php`) | Bills already have categories and monthly totals (Reports); budgets let the user set a monthly limit per category and see when they go over. |
| 2 | **Activity Log** | New module (`activity.php`) | Bills, payments and account changes can be deleted/undone; a per-user history shows what happened and when, including logins (security). |
| 3 | **Bills CSV export** | Enhancement (`bills.php`) | Payments already export to CSV; bills could not. Exports exactly what the current filters show. |

Schema changes (migration `database/migrations/001_budgets_activity_log.sql`):

- `budgets` — `user_id` + `category_id` (unique pair) → `monthly_limit DECIMAL(10,2)`. FK to users (cascade) and categories.
- `activity_log` — `user_id`, `action` (short code), `details`, `ip_address`, `created_at`. FK to users (cascade).

Rules:

- "Spent" in a budget = sum of the user's bills **due** in that month for that category (paid + unpaid), the same
  definition Reports uses for monthly expenses. Status: under 80% = on track, 80–100% = near limit, over 100% = over budget.
- Activity logging never breaks the action it records: a failed log write is swallowed.
- Logging is added to: register, login, failed login, logout, add/edit/delete bill, record/undo payment,
  profile update, password change, budget set/remove.
